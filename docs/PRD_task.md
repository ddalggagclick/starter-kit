# 상속길잡이 SDD 기반 PRD — 개발 태스크 

> **구성:** 에픽 8개·스토리 38개의 목적과 수락 기준은 [PRD_epic.md](./PRD_epic.md)를 따른다.
> **2026-10-20 MVP 변경:** 자동 추천·선정 순위는 제외한다. 초기 3문항과 위험 질문, 공통 8개 절차 및 확인 기능을 유지한다.

## 개발 태스크 — 144개

### 1-1-1. 카카오 공식 스킬 규격으로 관계·사망일/모름·안심상속 신청 여부 질문과 응답 버튼을 구현한다

**담당**  B2

**작업**  K-01(카카오 초기 3문항) 퀵리플라이 선택값은 고정된 선택지로 구성하고 다음 질문으로만 이동한다. 카카오 스킬 5초 제한을 준수한다.

**완료 조건**

- 초기 세 질문이 정해진 순서로 출력되고, 각 응답에 따라 다음 선택지만 노출된다.
- 관계·사망일의 모름·안심상속 신청 여부 값이 섞이지 않는다.
- 보안·예외 원칙: '모름'을 '아니요'로 변경하지 않고 상속인 자격·기한을 확정하지 않는다.

**구분**  1구간 V1 필수 / 완료

### 1-1-2. 스킬 JSON을 KakaoInputAdapter에서 공통 InitialAnswers로 변환한다

**담당**  B2

**작업**  플랫폼 필드를 B1의 상속 도메인 안내 타입으로 변환한다. 누락·잘못된 선택값은 422 등 입력 오류로 구분한다.

**완료 조건**

- 정상 카카오 스킬 JSON을 공통 InitialAnswers로 변환한다.
- 잘못된 값을 거부하고 원시 플랫폼 JSON을 공통 절차·안내 함수에 직접 전달하지 않는다.
- '모름'을 '아니요'로 변경하지 않는다.

**구분**  1구간 V1 필수 / 완료

### 1-1-3. 공통 8개 절차와 입력 기반 안내·위험 문구를 반환한다

**담당**  B1

**작업**  안내·위험 규칙은 LLM 없이 같은 입력·콘텐츠 버전에 같은 결과를 반환한다. 8개 전체 절차와 검수된 안내·위험 문구를 공통 DTO로 제공한다.

**완료 조건**

- 초기 답변과 관계없이 공통 8개 절차가 모두 제공된다.
- 검수된 안내·위험 문구만 확인된 입력 조건에 따라 달라진다.
- 카카오와 웹에서 안내 근거·콘텐츠 버전이 일치한다.

**구분**  1구간 V1 필수 / 완료

### 1-4-1. 카카오 최소 답변으로 10분 유효 서명 인계 토큰을 발급한다

**담당**  B2

**작업**  카카오가 [웹 체크리스트에서 보기]를 선택하면 관계·사망일/모름·안심상속·응답한 위험 질문만 A04로 보낸다. 백엔드는 HMAC-SHA256(`HANDOFF_HASH_KEY`) 서명 무상태 토큰을 발급한다. 사용자 ID·발화 원문은 제외하며 토큰을 DB에 저장하지 않는다.

**완료 조건**

- 토큰은 10분 뒤 만료되고 서명 위변조를 검사한다.
- 토큰과 사용자 답변의 원문을 로그에 남기지 않는다.
- 서버 재시작 후에도 만료 전 서명을 검증할 수 있다. base64 답변은 읽을 수 있고 암호화는 후속 과제다.
- 만료·위조·기소비·실패는 400 HANDOFF_INVALID와 동일한 안내로 처리한다.

**구분**  1구간 V1 필수 / 완료

### 1-4-2. 같은 서버에서 서명 인계 토큰의 10분 만료와 최초 1회 소비를 원자적으로 처리한다

**담당**  B1·통합

**작업**  서명 토큰의 만료를 확인하고 소비 이력만 동일 서버 인스턴스에 보관한다. 답변 페이로드는 서버 DB에 저장하지 않는다. 동일 인스턴스의 최초 소비를 잠금/원자적 처리로 보장한다.

**완료 조건**

- 동일 서버 인스턴스에서 동시 소비 시 최초 한 건만 성공한다.
- 만료·기소비·위조·실패에는 400 HANDOFF_INVALID를 반환한다.
- 재시작 뒤에도 서명 검증은 가능하지만 최초 1회 소비는 동일 서버 내에서만 보장된다.
- Handoff PostgreSQL 테이블을 생성하지 않는다.

**구분**  1구간 V1 필수 / 완료
